# نظام كاشير وإدارة مخازن قطع غيار السيارات (Offline-First POS)

نظام متكامل مخصص لمحلات قطع غيار السيارات، تم بناؤه باستخدام **Electron.js + React.js + TypeScript** ليعمل بشكل مستقل بالكامل دون اتصال بالإنترنت (Offline-First) مع مزامنة سحابية تلقائية في الخلفية لقاعدة بيانات **Supabase (PostgreSQL)** فور توفر الاتصال.

---

## 🚀 الميزات الرئيسية

1. **العمل بدون إنترنت (Offline-First)**: قراءة وكتابة محلية فائقة السرعة على قاعدة بيانات **SQLite** المحلية.
2. **طابور مزامنة ذكي (`sync_queue`)**: يقوم بتخزين جميع الحركات المحلية (فواتير بيع، حركات ديون الموردين، تعديلات المخازن) بشكل آمن بحالة (pending)، ومعالج خلفي (Sync Worker) يرفعها كسلسلة دفعات (Batches) للسيرفر السحابي فور عودة الشبكة.
3. **تعدد البدائل والمنشأ والربط المزدوج**:
   - يدعم تقسيم القطعة الواحدة لعدة بدائل (مثلاً: تيل فرامل: ألماني، صيني، كوري) بأسعار تكلفة وبيع مختلفة ومخزون منفصل.
   - جدول توافقية (`product_compatibility`) لربط كل قطعة بموديلات وسنوات السيارات المتوافقة معها.
4. **تنبيهات المخزون الحرج**: إطلاق تنبيه مرئي فوري ولون أحمر نابض في شاشة الكاشير والمخازن عند وصول رصيد القطعة الفعلي إلى الحد الأدنى المحدد لها أو أقل منه ($S_{current} \le S_{min}$).
5. **إدارة ديون الموردين وحركات التدقيق (Audit Trail)**:
   - جدول مستقل لتتبع ديون الموردين خطوة بخطوة بالوقت والتوثيق لمنع التلاعب.
   - ميزة "تسوية الدين بالكامل" بنقرة واحدة لتصفير مديونية المورد وتوليد حركة سداد مطابقة تلقائياً.
6. **سجل تتبع الحركات الصارم (`activity_logs`)**: توثيق فوري بالملي ثانية لأي حدث حساس (حذف صنف من السلة، فتح درج النقود الإلكتروني، تعديل جرد يدوي).
7. **تكامل العتاد والأجهزة (Hardware Integration)**:
   - **البار كود**: مستمع لوحة مفاتيح عام (Global Key Listener) مدمج بالواجهة للبحث التلقائي في SQLite وإدراج القطعة في السلة فوراً.
   - **طابعة الفواتير**: قالب طباعة حراري حقيقي مصمم بمقاس 80mm إجباري ومبني بالكامل على مكتبة `electron-pos-printer` لتفادي هوامش ومشاكل متصفح الويب التقليدي، ويدعم طباعة رمز الاستجابة السريع QR Code لإدارة المرتجعات.

## 🗄️ هياكل قواعد البيانات والتداول (Database Schemas)

### 1. المنتجات (`products`)
تخزين القطعة الأم العامة:
- `id` (نص - مفتاح رئيسي)
- `name` (نص - اسم القطعة العام، مثلاً: "تيل فرامل أمامي")
- `category` (نص - قسم القطعة)
- `min_limit_general` (رقم - الحد الأدنى العام)

### 2. بدائل المنتجات والمواصفات (`product_variants`)
ربط القطعة بالمواصفات الفنية والباركود والتسعير والمخازن:
- `id` (نص - مفتاح رئيسي)
- `product_id` (نص - مفتاح أجنبي يربط بالمنتج الأم)
- `origin` (نص - بلد المنشأ، مثلاً: "ألماني"، "صيني")
- `specification` (نص - التموضع أو الخصائص، مثلاً: "خلفي يمين")
- `cost_price` (عشري - سعر التكلفة)
- `selling_price` (عشري - سعر البيع الفعلي)
- `stock_quantity` (رقم - المخزون الفعلي الحالي في المحل)
- `min_limit` (رقم - الحد الأدنى الفردي للبديل $S_{min}$)
- `sku_barcode` (نص - الباركود الفريد المطبوع على العلبة)

### 3. التوافقية مع موديلات السيارات (`product_compatibility`)
ربط البديل بنوع وموديل وسنة السيارة:
- `id` (نص - مفتاح رئيسي)
- `variant_id` (نص - مفتاح أجنبي للبديل)
- `car_make` (نص - الشركة المصنعة، مثلاً: Toyota)
- `car_model` (نص - الموديل، مثلاً: Corolla)
- `year_start` (رقم - بداية سنة الصنع المتوافقة)
- `year_end` (رقم - نهاية سنة الصنع المتوافقة)

### 4. طابور العمليات المزامنة (`sync_queue`)
- `id` (نص - مفتاح رئيسي)
- `table_name` (نص - اسم الجدول المتأثر)
- `operation` (نص - INSERT أو UPDATE)
- `record_id` (نص - المعرف الفريد للبيانات)
- `data` (نص - مصفوفة البيانات بصيغة JSON String)
- `status` (نص - pending أو synced أو failed)
- `error_message` (نص - رسالة الخطأ إن وجدت)

## ⌨️ اختصارات لوحة المفاتيح المدمجة بالكاشير

- **[F2]**: إتمام ودفع قيمة الفاتورة الحالية وطباعتها فورياً على الطابعة الحرارية 80mm وإعادة تهيئة السلة.
- **[F5]**: إلغاء وتفريغ السلة بالكامل وإعادة التهيئة دون الحاجة لاستخدام الماوس (تم حظر سلوك المتصفح الافتراضي لإعادة تحميل الصفحة).
- **قارئ الباركود (Barcode Scanner)**: يعمل تلقائياً بمجرد تمرير باركود القطعة؛ حيث يقوم النظام بمسحه والبحث اللحظي في SQLite، ومن ثم إدراجه مباشرة في السلة بزيادة كمية قدرها `1`.

## 🛠️ تعليمات التشغيل والتطوير المحلي

### متطلبات التشغيل
* تثبيت بيئة عمل Node.js (الإصدار 18 فما فوق).
* للتشغيل الحقيقي كـ Desktop App: يُفضل توفر بيئة تجميع أدوات C++ لوحدات الـ Node Native (لتجميع مكتبة SQLite better-sqlite3 بنجاح).
* *تنويه*: في حال عدم توفر أدوات تجميع SQLite المحلية أو تشغيل النظام بالكامل في المتصفح العادي، يقوم معالج البيانات (`dbClient.ts`) بالتحول تلقائياً لوضع **Fallback Memory & LocalStorage DB** لضمان عمل كافة ميزات الكاشير والموردين والحركات والمخازن فوراً دون أي توقف أو شاشة بيضاء.

### خطوات التشغيل والتجربة:

1. قم بتثبيت المكونات والاعتمادات:
   ```bash
   npm install
   ```

2. تشغيل سيرفر الويب وتطبيق Electron في وضع التطوير والتتبع (Hot-Reload):
   ```bash
   # تشغيل واجهة React في الخلفية
   npm run dev
   
   # وفي ترمينال آخر تشغيل نافذة ديسكتوب إلكترون
   npm run electron:dev
   ```

3. لبناء وتجميع التطبيق لملف تنفيذي مستقل للويندوز أو اللينكس:
   ```bash
   npm run build
   npm run electron:build
   ```
